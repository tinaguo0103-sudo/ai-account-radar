# Austin不加班脚本Skill

这个 Skill 把已确认选题转成一页脚本大纲确认稿。它不是口播成稿器，也不是完整执行包生成器；完整脚本、提词器、录屏清单、后期交接和发布包放到 `06` 再生成。

## 核心原则

1. 先承接 `04 工作流实验命题卡`，不要从短标题重新理解选题。
2. `04` 回答“为什么值得做、做什么实验、怎么验证、沉淀什么资产”；本 Skill 在 `05` 只回答“核心观点怎么成立、视频结构怎么走、06需要拿什么继续生成”。
3. v0.2 默认只输出一份给人看的 `script_outline_brief.md`，不要拆成一堆让用户难以阅读的文件。
4. v0.2 不生成完整脚本包，不自动拆 `06 内容任务主表`；只有人工确认大纲后，`06` 才生成完整脚本和执行方案。
5. 涉及产品能力、平台规则、价格、政策、数据时，必须标记为需事实核验。
6. 如果 `需要补的证据` 是公开可检索资料、官方原文、政策日期、产品官网卖点或公开样本，Codex 使用本 Skill 时要先主动检索和引用，搜不到或无法核验时才标为缺口。
7. 公开资料和可拍摄素材要分开：官网、公示、公告是事实依据；自己的截图、字段表、失败样例、人工修正点才是制作证据。
8. 口吻要像真实业务实战分享，保留人工判断、失败边界、修正点和资产沉淀。
9. 05 是给奥斯汀本人看的判断稿，不是给观众看的课程讲义。不要使用“这条视频的钩子不是单纯讲”“论据要落在两个地方”“这一段要让观众相信”“结构按……走”等模板句；优先写成“我想拿它测什么”“旧流程哪里卡”“画面里要拿出什么”“最后怎么复用”。
10. 视频大纲不能只是时间段和步骤，要写出每段的“戏剧任务”：开头有什么结果感，旧流程和新动作的冲突是什么，中段实验要回答什么问题，证据/失败样例带来什么转折，最后资产如何复用。
11. 用户判断一条 05 能不能继续拍，第一眼要先看到开头钩子、中段关键判断和可用金句；这些内容要放在核心观点和视频大纲前面，帮助用户快速判断这条视频有没有拍摄欲望。

## v0.2 工作流

1. 把输入映射为 Topic Card。
2. 校验必填字段，输出 `pass/revise/blocked`。
3. 判断六类脚本模板之一。
4. 生成一页脚本大纲确认稿：核心观点、视频大纲、给06的生成输入。
5. 输出单一主文档 `script_outline_brief.md`；飞书只保存索引、核心观点、大纲、给06的生成输入和本地文档路径。

## 资源使用

- 需要批量渲染脚本大纲确认稿时，运行 `scripts/batch_render.py`。
- 需要只校验 Topic Card 时，运行 `scripts/validate_topic_card.py`。
- 需要汇总某天输出时，运行 `scripts/merge_daily_index.py`。
- 需要字段映射细节时，读 `integrations/feishu_bitable_mapping.md`。
- 需要修改输出格式时，优先修改 `templates/`，再调整脚本。

## 输出文件契约

每个选题输出目录默认只包含：

```text
script_outline_brief.md
```

这份主文档必须保留用户真正需要看的内容，并且只做大纲确认，不做完整执行稿。默认章节顺序只有四块：

1. `先看能不能拍`：先给开头钩子候选、中段关键判断、可用金句，让用户立刻判断这条有没有拍摄欲望。
2. `核心观点`：几句话讲清论点、论据、钩子和最后要收束成什么资产，不只写一句口号。
3. `视频大纲`：按时间线展开视频结构，包括开场钩子、真实现场、观点定调、实验主线、证据/反例和资产收束。
4. `给06的生成输入`：把推荐模板、必须展开的实操主线、关键证据、P0素材、事实核验和私有表达边界交给06。

不要一上来铺满口播轨、后期轨和散点清单。用户打开文件后，30 秒内必须知道这条内容的观点是否成立、视频怎么展开，以及 06 应该继续生成什么。

## 模板类型

只使用这六类模板：

1. `Skill公开型`
2. `热点业务转译型`
3. `认知定调型`
4. `真实工作流改造型`
5. `Agent实战型`
6. `项目复盘型`

无法判断时默认使用 `真实工作流改造型`。

## 安全边界

- 仓库版本是公开脱敏版，不包含真实客户、未公开项目、敏感素材或账号内部私密判断。
- 全局私有版可以在 `references/private/` 等本地目录补充敏感素材，但不要提交到 Git。
- 不要把完整脚本当成事实核验完成的发布稿。
- 不要自动发布、自动剪辑、自动声称工具能力已验证。
