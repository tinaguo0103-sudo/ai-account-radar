# Austin不加班脚本Skill

这个 Skill 把已确认选题转成两类生产稿：

- `05`：一页脚本大纲确认稿，用于快速判断观点、结构和是否值得继续。
- `06`：完整口播稿与执行包，用于已经确认推进的选题，输出口播全文、录屏清单、剪辑交接、发布包和 QA。

口播全文不在本 Skill 内硬塞风格规则；生成 `06` 时优先交给独立 Skill `austin-voice-scriptwriter` 处理真人口播语气。本 Skill 保持为流程、证据、执行包和飞书衔接层。

## 核心原则

1. 先承接 `04 工作流实验命题卡`，不要从短标题重新理解选题。
2. `04` 回答“为什么值得做、做什么实验、怎么验证、可能沉淀什么资产”；本 Skill 在 `05` 只回答“核心观点怎么成立、视频结构怎么走、06需要拿什么继续生成”，不要替用户锁死具体案例或最终资产。
3. `05` 默认只输出一份给人看的 `script_outline_brief.md`，不要拆成一堆让用户难以阅读的文件。
4. 用户明确要继续生成时，`06` 输出单一主文档 `full_script_execution_package.md`，不要恢复成 00-08 多文件散包。
5. 涉及产品能力、平台规则、价格、政策、数据时，必须标记为需事实核验。
6. 如果 `需要补的证据` 是公开可检索资料、官方原文、政策日期、产品官网卖点或公开样本，Codex 使用本 Skill 时要先主动检索和引用，搜不到或无法核验时才标为缺口。
7. 公开资料和可拍摄素材要分开：官网、公示、公告是事实依据；自己的截图、字段表、失败样例、人工修正点才是制作证据。
8. 口吻要像真实业务实战分享，保留人工判断、失败边界、修正点和可选沉淀方向。
9. 05 是给奥斯汀本人看的判断稿，不是给观众看的课程讲义。不要使用“这条视频的钩子不是单纯讲”“论据要落在两个地方”“这一段要让观众相信”“结构按……走”等模板句；优先写成“我想拿它测什么”“旧流程哪里卡”“画面里要拿出什么”“最后怎么复用”。
10. 视频大纲不能只是时间段和步骤，要写出每段的“戏剧任务”：开头有什么结果感，旧流程和新动作的冲突是什么，中段实验要回答什么问题，证据/失败样例带来什么转折，最后如何判断是否进入06。
11. 用户判断一条 05 能不能继续拍，第一眼要先看到开头钩子、中段关键判断和可用金句；这些内容要放在核心观点和视频大纲前面，帮助用户快速判断这条视频有没有拍摄欲望。
12. 钩子、关键判断、金句三者必须分工清楚：
    - `钩子` 是前 3-5 秒的注意力入口，必须给风险、冲突、反常识或结果悬念；不要写成“今天我要做什么”。
    - `关键判断` 是这条内容真正站住的立场，必须包含业务后果、判断标准或证据线；不要复述流程步骤。
    - `金句` 是可被单独引用的 sound bite，要短、可传播、能概括立场；不要把普通短句当金句。
13. 参考真实视频前期制作写法：大纲是拍摄路线图，不是说明文。每段优先用短句和动作句，只写“拍什么 / 说哪句 / 给什么证据 / 下一步是什么”。避免“这一段的重点是”“要让观众相信”“不是X而是Y”的解释腔。
14. `暂无`、`待补实验动作`、`待补旧流程痛点` 等占位内容不能当成真实字段使用；缺字段就标记 blocked 或待补，不要硬生成看似完整的脚本大纲。
15. 同一批 05 输出不能只换字段套同一套骨架；不同题材要走不同拍摄路线。Agent 题要看任务追责，选题/候选池题要看前后对比和错误回写，视觉交付题要看导出稳定和人工修正，创意返修题要看修改意见是否命中、能否少掉一轮返修，汽车风险题要看边界和证据，blocked 题要直接写为什么先不拍。

## 工作流

1. 把输入映射为 Topic Card。
2. 校验必填字段，输出 `pass/revise/blocked`。
3. 判断六类脚本模板之一。
4. `05` 生成一页脚本大纲确认稿：核心观点、视频大纲、给06的生成输入。
5. `06` 生成完整口播稿与执行包：一屏结论、视频结构、口播全文、分段执行方案、录屏与素材清单、剪辑交接、发布包草稿、QA。
6. 飞书只保存索引、核心摘要和本地文档路径；完整内容以本地 Markdown 为主。

## 资源使用

- 需要批量渲染脚本大纲确认稿时，运行 `scripts/batch_render.py`。
- 需要从飞书 04 指定记录生成完整执行包时，运行仓库脚本 `scripts/generate_script_execution_package.py --record-id <04_record_id> --write-feishu`。
- 需要调整真人口播风格时，修改独立 Skill `austin-voice-scriptwriter`；本 Skill 的渲染脚本会优先读取全局私有版 `/Users/congcong/.codex/skills/austin-voice-scriptwriter`，缺失时才使用仓库脱敏版。
- 需要只校验 Topic Card 时，运行 `scripts/validate_topic_card.py`。
- 需要汇总某天输出时，运行 `scripts/merge_daily_index.py`。
- 需要字段映射细节时，读 `integrations/feishu_bitable_mapping.md`。
- 需要修改输出格式时，优先修改 `templates/`，再调整脚本。

## 输出文件契约

每个选题输出目录默认只包含：

```text
script_outline_brief.md
```

这份主文档必须保留用户真正需要看的内容，并且只做大纲确认，不做完整执行稿。默认章节顺序只有四块：

1. `先看能不能拍`：先给开头钩子候选、中段关键判断、可用金句，让用户立刻判断这条有没有拍摄欲望。
2. `核心观点`：几句话讲清论点、论据、钩子和为什么值得继续生成06，不只写一句口号。
3. `视频大纲`：按时间线展开视频结构，包括开场钩子、真实现场、观点定调、实验主线、证据/反例和收尾判断。每段要像拍摄指令，少解释，多给动作。
4. `给06的生成输入`：把推荐模板、必须展开的实操主线、证据建议、待补素材、事实核验和私有表达边界交给06。案例锚点和资产只能作为参考，不强制用户使用。

不要一上来铺满口播轨、后期轨和散点清单，也不要在05替用户指定必须使用的案例或资产。用户打开文件后，30 秒内必须知道这条内容的观点是否成立、视频怎么展开，以及 06 应该继续生成什么。

当生成 `06` 时，每个选题输出目录只新增一个主文件：

```text
full_script_execution_package.md
```

这份文档面向制作执行，必须开头先给结论和待办，再展开口播全文、录屏清单、剪辑交接和发布包草稿。不要把执行包拆回多个文件。

## 模板类型

只使用这六类模板：

1. `Skill公开型`
2. `热点业务转译型`
3. `认知定调型`
4. `真实工作流改造型`
5. `Agent实战型`
6. `项目复盘型`

无法判断时默认使用 `真实工作流改造型`。

## 安全边界

- 仓库版本是公开脱敏版，不包含真实客户、未公开项目、敏感素材或账号内部私密判断。
- 全局私有版可以在 `references/private/` 等本地目录补充敏感素材，但不要提交到 Git。
- 不要把完整脚本当成事实核验完成的发布稿。
- 不要自动发布、自动剪辑、自动声称工具能力已验证。
