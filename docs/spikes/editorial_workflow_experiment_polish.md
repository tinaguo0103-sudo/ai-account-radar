# 工作流实验命题卡可读性与可执行性打磨

上一轮 `0f4a77b` 已经把 `04 分析与选题` 的方向改对了：它不再是标题榜，而是工作流实验命题卡候选池。本轮不推翻这个方向，不做新架构，不优化发布标题，不新增字段，不重新采集内容。

本轮只打磨三件事：

1. `选题命题` 更短、更自然，不把完整拆解塞进第一列。
2. `验证方式` 变成 1-2 步可执行的最小实验动作。
3. `可沉淀资产` 具体到这条选题，而不是通用资产包。

## 字段边界

`选题命题` 是内部工作台上的短命题，不是完整脚本包，也不是可发布标题。它只说明：这条外部素材触发了我哪个工作流实验。建议 35-70 字，最多不超过 90 字。

`选题命题` 不应该批量写成同一种句式，例如：

- `我想用 X 测试 Y 能不能 Z`
- `我准备用 X 验证 Y 能不能 Z`
- `用 X 测试 Y 能不能进入 Z`

这些句式可以偶尔出现，但不能成为整批候选的默认骨架。

`我要做的实验` 继续保留，用来写清我会拿这条素材去测试、改造、压缩、复用或验证哪段真实流程。

`验证方式` 必须是最小实验步骤。它要说清输入材料、动作、输出物和通过/失败标准。不能只写“检查是否可用”“对比旧流程和新流程”。

`可沉淀资产` 必须是具体资产名，例如 `选题判断表`、`Brief入口字段`、`封面返工记录表`、`分镜返修记录表`、`短片Agent验收表`。不要写成 `Workflow SOP / 字段规则 / Brief 模板 / QA 清单` 这类通用包。

## 代码边界

内容判断仍由 `ai-account-editorial-director` Skill 完成。代码只做：

- 字段长度和必填保护；
- `title_permission` 与 `可发布标题 / 标题备选` 的一致性；
- 飞书写入和读回校验；
- 阻止泛资产包、不可执行验证方式和批量重复命题句式。

代码不再按栏目兜底生成“视频=分镜QA”“Agent=任务回填”“汽车=内容资产流”这类创意模板。如果 Skill 没给出具体判断，代码会暴露 `待补`，而不是假装完成主编判断。

## 固定输入

本轮使用固定输入重跑，不重新采集：

```text
output/latest_write/today_10_topics.csv
```

不拉 AIHOT，不拉公众号 feed / wewe-rss，不采样抖音，不解析新 URL。重跑后写入飞书 `04 分析与选题`，方便直接在飞书里看效果。

## 验收标准

- `选题命题` 第一眼更像工作台条目，而不是长分析段。
- 同批候选不再批量出现“我想用 X 测试 Y 能不能 Z”。
- 每条可见候选仍保留清晰的 `我要做的实验`。
- `验证方式` 能照着做，包含输入、动作、输出或验收标准。
- `可沉淀资产` 是 1-3 个具体资产名。
- `title_permission != 可发布标题` 时，`可发布标题 / 标题备选` 继续为空。
- 抖音浅层内容不越界声称口播、评论、镜头结构或完整视频理解。
