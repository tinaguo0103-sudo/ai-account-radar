# 04 工作流实验命题卡重构说明

本轮重构不是继续优化标题，而是把 `04 分析与选题` 的核心产品语义从“选题命题卡”升级为“工作流实验命题卡”。

上一轮把 `04` 从“标题候选池”改成“选题命题卡候选池”，方向是对的：发布标题不再是第一字段，`可发布标题 / 标题备选` 只在 `title_permission=可发布标题` 时后置生成。

但最新结果暴露出两个问题：

1. `选题命题` 容易写得太长，像把完整拆解塞进第一列。
2. 主语义仍偏“解释这个素材为什么符合人设”，而不是直接提出“我拿这个热点去测试、改造、压缩、复用或验证自己的哪段真实工作流”。

## 新语义

`04` 的核心产物升级为工作流实验命题卡。

好选题必须回答：

```text
外部热点触发点
+ 我的工作流痛点
+ 我要做的实验
+ 旧流程痛点
+ AI介入点
+ 验证方式
+ 可沉淀资产
```

外部热点、公众号文章、抖音对标内容都只是触发器。真正的候选不是“这个热点怎么讲”，而是“我准备用这个外部变化测试、改造、压缩、复用或验证自己的哪段业务流程”。

例如 Codex Record 这类能力，普通 AI 号会讲“Codex 新增录制工作流功能”。工作流实验命题卡应该写成：

```text
选题命题：我想用 Codex Record 测一件事：剪辑经验能不能被录成可复用 Skill
我要做的实验：录一段真实剪辑流程，检查 Codex Record 能不能生成可读、可复跑、能保留验收规则的剪辑 Skill。
```

## 字段职责

- `选题命题`：短命题，不是完整拆解，也不是可发布标题。建议 35-70 字，最多不超过 90 字。
- `我要做的实验`：最核心字段，必须有测试、改造、压缩、录成 Skill、接进流程、变成验收表、沉淀 SOP 等动作。
- `热点触发点`：外部素材触发了什么。
- `我的工作流痛点`：它撞上了我的哪段真实生产痛点。
- `旧流程痛点`：过去怎么做，为什么麻烦，卡在哪里。
- `AI介入点`：AI 到底改了旧流程中的哪一步。
- `验证方式`：我怎么证明这个实验成立。
- `可沉淀资产`：如果成立，最后能沉淀成什么。
- `可发布标题`：后置包装字段，只在 `title_permission=可发布标题` 时出现。

## Skill 流程

主编层从：

```text
Gate -> Topic Proposition Card -> Title Packaging
```

升级为：

```text
Gate -> Workflow Experiment Card -> Title Packaging
```

代码不负责创意判断。代码只负责字段语义、门控保护、写入保护和一致性校验；真正的内容判断仍由 `ai-account-editorial-director` Skill 完成。

## 写入与测试边界

本轮测试使用固定输入：

```text
output/latest_write/today_10_topics.csv
```

或飞书 `04` 最近批次 `run_20260620_topic_proposition_refactor_check` 的等价结果。

本轮不重新采集，不拉 AIHOT，不拉公众号 feed / wewe-rss，不采样抖音，不解析新 URL，不改 `03 内容收件箱`。只重跑主编 Skill，写入新的 `04 分析与选题` 运行批次，并刷新 `00 主控台`。

## 验收标准

- `04` 第一眼看到的是短 `选题命题`，不是长段拆解。
- 每条可见候选都有 `我要做的实验`。
- 可见候选能看出热点触发了哪个工作流痛点。
- `旧流程痛点 / AI介入点 / 验证方式 / 可沉淀资产` 被拆到独立字段。
- `可发布标题` 仍然后置。
- `title_permission` 只控制标题包装，不控制命题卡是否存在。
- 抖音浅层内容不能越界声称口播全文、评论区、镜头结构或完整视频理解。

## 后续可读性打磨

`0f4a77b` 完成语义重构后，下一轮只做可读性与可执行性打磨，不再推翻架构。重点见 `docs/spikes/editorial_workflow_experiment_polish.md`：

- `选题命题` 继续保持短命题，但要更自然，不能整批都像“我想用 X 测试 Y 能不能 Z”。
- `验证方式` 必须变成 1-2 步最小实验动作，写清输入、动作、输出或验收标准。
- `可沉淀资产` 必须具体到该选题，避免通用 `Workflow SOP / 字段规则 / Brief 模板 / QA 清单`。
