# 04 选题命题卡重构说明

本轮重构的目标不是把标题写得更像真人，而是把 `04 分析与选题` 从“标题候选池”改成“选题命题卡候选池”。

> 2026-06-20 后续更新：本轮语义已经进一步升级为“工作流实验命题卡”。`选题命题` 现在只承担短命题职责，不再承载完整拆解；核心新增字段是 `我要做的实验 / 热点触发点 / 我的工作流痛点 / 验证方式 / 可沉淀资产`。详见 `docs/spikes/editorial_workflow_experiment_refactor.md`。

## 为什么要改

过去 `04` 的主字段和写入逻辑都偏向 `可发布标题`。这会带来两个问题：

1. 系统会过早进入标题包装，导致候选看起来像一批标题，而不是一批可判断的内容命题。
2. 当某条内容只有内部测试价值、需要补证据或不适合发布标题时，它仍然容易被迫生成标题，最后变成模板化、AI味重、和账号人设不够贴合。

真正要判断的是：这条外部素材能不能被我讲成自己的业务现场？如果能，它对应哪个场景、旧流程痛点是什么、AI介入哪一步、我准备证明什么、还缺什么证据。

## 新语义

`04` 的核心不再是标题，而是 `选题命题`。

`选题命题` 不是原始标题，也不是发布标题。它回答：

- 这个外部素材如何变成我的账号选题；
- 它接到我的哪个真实或相邻业务场景；
- 旧流程原来卡在哪里；
- AI 具体介入哪一步；
- 我准备讲出什么判断；
- 我能展示什么证据，缺什么证据。

一个合格的 `选题命题` 可以暂时没有可发布标题，但不能没有场景、判断和证据边界。

## 新流程

主编层从：

```text
Gate -> Pitch -> Title
```

调整为：

```text
Gate -> Topic Proposition Card -> Title Packaging
```

### 1. Gate / 主编门控

先判断这条素材是否值得进入我的候选池：

- 是否只是资讯搬运；
- 是否能接到我的四个方向；
- 是否能接到真实或相邻业务现场；
- 证据是否足够；
- 是否能讲清旧流程痛点、AI介入点、人保留的判断和可展示结果。

### 2. Topic Proposition Card / 选题命题卡

通过门控后，生成给我判断的命题卡。核心字段是：

- `选题命题`
- `对应方向`
- `我的场景拆解`
- `旧流程痛点`
- `AI介入点`
- `我的思考点`
- `重点体现`
- `可展示证据`
- `需要补的证据`
- `候选状态`
- `推荐等级`
- `推荐动作`

这些字段要像我拍摄前写给自己的判断备忘，不要像助理总结，也不要像资讯标题。

### 3. Title Packaging / 标题包装

只有当 `title_permission=可发布标题` 时，才生成：

- `可发布标题`
- `标题备选`

如果是 `内部测试标题` 或 `不生成标题`：

- `选题命题` 仍然可以保留；
- `可发布标题` 和 `标题备选` 必须为空；
- 不能为了让前台好看而强行包装标题。

## 04 字段语义

前台应该优先看：

1. `选题命题`
2. `候选状态`
3. `推荐等级`
4. `对应方向`
5. `我的场景拆解`
6. `旧流程痛点`
7. `AI介入点`
8. `我的思考点`
9. `重点体现`
10. `可展示证据`
11. `需要补的证据`
12. `title_permission`
13. `可发布标题`
14. `标题备选`
15. `不建议做原因`
16. `来源标题`
17. `来源链接`
18. `运行批次`

如果飞书主字段暂时仍叫 `选题标题`，也要写入命题式文本，而不是发布标题。发布标题只放在 `可发布标题` 字段里。

## 成功标准

- 打开 `04` 后，第一眼看到的是“我准备讲什么命题”，不是一批标题。
- `title_permission` 只控制是否给发布标题，不控制是否能成为内部候选命题。
- `内部测试标题` 和 `不生成标题` 可以有命题卡，但不能残留发布标题。
- `今日最值得做` 必须是命题、场景、证据都更完整的候选。
- `可选候选` 可以是需要补证据的命题卡。
- 不值得成为命题卡的内容，不进入 `04` 前台候选。
