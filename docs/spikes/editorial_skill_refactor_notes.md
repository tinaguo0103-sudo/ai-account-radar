# ai-account-editorial-director Skill 减法重构审计

本轮目标不是继续补标题模板，而是把主编层从“标题工作坊产出器”收回到“判断核心”。

## 审计结论

1. 旧版 Skill 的人设、案例方向是对的，但主流程太重。
2. `标题工作坊`、`标题自审` 被要求为强候选必填字段，模型会为了完成字段而批量发散标题，容易从一个模板变成多个模板。
3. `我会把 X...`、`X 真正卡住的不是...`、`X 对我有用...` 这些句式本来是表达参考，但在批量任务里会变成生成模板。
4. 代码层之前没有 `title_permission`，导致“有方向但不够发布”的候选也可能残留可发布标题。
5. 抖音浅层内容、AIHOT 摘要、公众号全文应该用不同证据门槛判断，而不是统一进入标题生成。
6. 真正需要稳定的是 `Gate -> Topic Proposition Card -> Title Packaging`：先判断能不能成为用户自己的内容，再生成选题命题卡，最后才决定是否生成可发布标题。

## 本轮修复口径

- `标题工作坊`、`标题自审` 降级为调试字段，不再作为主流程必填。
- 新增 `title_permission`：
  - `可发布标题`：允许写入前台 `可发布标题 / 标题备选`。
  - `内部测试标题`：可作为内部判断，但不能伪装成可发布标题。
  - `不生成标题`：暂存、不建议、仅热点观察或证据不足。
- 飞书写入层二次防护：只要 `title_permission != 可发布标题`，即使 CSV 残留标题，也会清空 `可发布标题 / 标题备选`。
- 回归校验和飞书读回校验同步检查 `title_permission`，防止旧字段残留。

## 保留原则

Skill 仍然必须读取 `persona-brief.md` 和案例库，但案例库是经验锚点，不是标题模板库。选题要从用户真实/相邻业务现场里长出来，而不是从句式库里拼出来。
