# 学习反馈闭环方案

本文描述 AI账号信息雷达的学习闭环设计。原则是先收集真实反馈，再生成每日学习日结，最后由人工确认后沉淀到规则或 Skill；测试环境和生产环境的任何表、文档、文件夹、通知目标都不能混用。

## 目标

把两类人工反馈变成可追踪、可确认、可迭代的学习资产：

- 选题反馈：用户在第一张选题卡里选择、暂存、归档或不做的判断。
- 内容反馈：用户在 `06 完整脚本与制作包` 完成卡里对脚本质量、问题标签和修改意见的反馈。

第一阶段不自动改全局私有 Skill，不自动影响生产主编判断。系统只生成学习摘要，并把待学习记录推进到“待确认学习”。确认后再进入下一轮规则沉淀。

## 硬约束：测试与生产隔离

测试和生产不能共用同一套飞书表、文档文件夹或通知目标。任何会写飞书、发卡、生成文档、标记学习状态的测试，都必须使用 staging/test 配置。

隔离要求：

- 测试表不能写生产业务表。比如 `06` 测试必须写 `06 完整脚本与制作包__测试`，通过 `FEISHU_SCRIPT_PACKAGE_TABLE_ID` 指向。
- 测试飞书文档不能写生产文件夹。测试必须使用 `06完整脚本与制作包_TEST` 或后续学习专用测试文件夹。
- 测试通知不能发正式群。测试卡、学习日结、失败 QA 演练默认发个人 open_id。
- 测试学习记录不能写生产学习表。后续如果创建 `08 学习记录`，必须同时创建 `08 学习记录__测试`。
- 显式测试环境必须通过 `AI_ACCOUNT_RADAR_ENV_FILE=.env.staging.local` 或 `AI_ACCOUNT_RADAR_ENV=staging` 加载；显式 env 文件不会回退读取 `.env.local`。
- 预合并测试允许读生产只读数据，但不允许写生产业务表、生产文档文件夹或正式群通知。

后续实现任何新学习脚本时，默认必须具备 `--dry-run` 和显式 env 支持；如果要写飞书，脚本需要在输出里打印目标 Base、目标表、目标文件夹和通知目标。

## 当前基础

已有能力：

- `04 分析与选题` 已有 `学习状态` 字段和 `待学习样本` 视图。
- `scripts/learn_from_topic_selection.py` 已能读取选题选择结果，生成本地学习摘要，并支持 `待确认学习 / 已学习` 状态推进。
- `06 完整脚本与制作包` 已有质量反馈字段：`人工质量反馈`、`质量问题标签`、`人工修改意见`、`反馈时间`、`反馈来源`、`内容学习状态`。
- dev/staging 已验证 06 完成卡可以把三段反馈写回测试 `06` 表，并标记 `内容学习状态=待学习`。

缺口：

- 选题学习和内容学习还没有合并成同一张每日学习日结。
- 还没有独立的 `08 学习记录 / 08 学习记录__测试`。
- 还没有学习日结飞书卡，也没有“采纳 / 部分采纳 / 暂不采纳”的回写动作。
- 还没有把已确认学习结果同步到私有 Skill 的流程。

### 04 分析与选题

继续使用现有字段：

- `学习状态`：`待学习 / 待确认学习 / 已学习 / 忽略`

建议补充字段：

- `选择学习批次`
- `选择学习摘要`

### 06 完整脚本与制作包

继续使用现有字段：

- `人工质量反馈`
- `质量问题标签`
- `人工修改意见`
- `反馈时间`
- `反馈来源`
- `内容学习状态`

建议补充字段：

- `内容学习批次`
- `内容学习摘要`

### 08 学习记录

生产表：`08 学习记录`  
测试表：`08 学习记录__测试`

建议字段：

- `学习批次`
- `学习日期`
- `环境`：`production / staging`
- `学习类型`：`选题 / 内容 / 综合`
- `样本数量`
- `选题样本数`
- `内容反馈样本数`
- `学习结论`
- `建议沉淀规则`
- `不应沉淀的个案`
- `关联04记录`
- `关联06记录`
- `确认状态`：`待确认 / 已采纳 / 部分采纳 / 暂不采纳`
- `确认时间`
- `确认备注`
- `Skill同步状态`：`未同步 / 待同步 / 已同步 / 不同步`

## 每日学习日结

建议每天一次，下午或晚上运行，不在白天零散通知。

流程：

```text
读取 04 待学习选题反馈
-> 读取 06 待学习内容反馈
-> 聚合成学习日结 Markdown/JSON
-> 写入 08 学习记录
-> 发送一张学习日结卡给个人
-> 用户选择采纳/部分采纳/暂不采纳
-> 回写 08，同时标记关联 04/06 记录
```

学习日结内容：

- 今日更愿意推进的选题类型。
- 今日被暂存、不做或归档的选题类型。
- 06 脚本最常见问题。
- 应沉淀为长期规则的内容。
- 只属于个案、不应沉淀的内容。
- 建议写入 Skill 的候选规则。

## 规则沉淀分层

学习结果分三层处理：

- 硬规则：以后必须遵守，适合写入长期规则或脚本校验。
- 偏好规则：影响生成方向，但允许例外，适合写入私有 Skill reference。
- 个案记忆：只作为当天/某项目上下文，不进入长期 Skill。

自动化初期只生成建议，不直接修改全局私有 Skill。人工确认后，再由 Codex 把稳定规则同步到 Skill reference。

## 实施阶段

### P0：文档与隔离规范

- 明确测试/生产隔离规则。
- 预合并测试必须使用测试表、测试文件夹和个人通知目标。
- 学习闭环所有写入脚本必须支持显式 staging env。

### P1：本地学习日结 dry-run

新增脚本：`scripts/learn_from_daily_feedback.py`

能力：

- 读取 `04` 待学习样本。
- 读取 `06` 待学习质量反馈。
- 生成本地 Markdown/JSON 学习日结。
- 默认 dry-run，不写飞书。

### P2：测试环境写入闭环

新增或扩展测试环境脚本：

- 创建/复用 `08 学习记录__测试`。
- staging env 写入测试学习记录。
- 发送学习日结卡到个人 open_id。
- 模拟卡片提交并读回测试表确认状态。

### P3：生产上线

上线前要求：

- staging 已验证 04/06/08 三表写入。
- staging 已验证学习日结卡只发个人。
- receiver 支持学习日结确认动作并已通过单测。
- 生产部署 receiver 后，再启用生产学习卡。

生产运行策略：

- 每天一次。
- 无待学习样本时不发卡，或只写本地空摘要。
- 学习卡只发个人，不发正式内容群。

### P4：Skill 同步

新增“待同步 Skill 规则草稿”：

- 从已采纳学习记录里提取稳定规则。
- 写入本地草稿文件。
- 人工确认后同步到全局私有 Skill reference。

## 对抗性审查

上线前必须验证：

- staging 不会回退读取生产 `.env.local`。
- staging 的 04/06/08 表 ID 都不是生产表 ID。
- staging 文档 URL 落在测试文件夹。
- staging 卡片只发个人 open_id。
- 生产只读检查不会写任何业务表。
- 学习卡过期或重复提交不会重复标记记录。
- 单条极端反馈不会直接升级为长期规则。
- 用户选择“暂不采纳”后，不会把关联 04/06 标为已学习。
