# AI Account Editorial Director Skill

`ai-account-editorial-director` 是本项目的全局选题编辑 Skill，用来把 AIHOT、公众号全文、抖音对标内容、对标账号结构和本地候选池，转成更贴近用户人设的选题判断。

它不是采集脚本，也不是自动成稿器，也不是标题模板器。它负责“主编判断”：这条内容能不能被我讲成自己的选题、应该接到哪个生产现场、我能补什么经验、重点体现什么、是否值得进入 Brief。

最新版本已经把长案例库提炼成 Skill 可直接使用的主编直觉：案例库不是硬边界，而是人设、风格和场景推演的基底。Skill 不再要求每条候选必须机械绑定一个已有案例；它可以基于用户人设和案例样本做合理的相邻场景推演，但必须说明证据边界，不能假装用户做过没有证据的事。

## Skill 文件结构

```text
ai-account-editorial-director/
├── SKILL.md
├── agents/
│   └── openai.yaml
└── references/
    ├── persona-brief.md
    └── persona-and-cases.md
```

- `SKILL.md`：触发条件、主编判断流程、四个方向的核心判断、案例使用方式、禁用表达和质量底线。
- `references/persona-brief.md`：从完整案例库提炼出的运行底稿。它直接写清人设、五个母场景、标题风格、候选分级和抖音浅层边界，是每次自动判断优先使用的文件。
- `references/persona-and-cases.md`：完整人设与案例档案，用来追溯细节和继续扩展案例，不作为每次批量判断时唯一依赖的长上下文。
- `agents/openai.yaml`：用于技能列表展示的名称、描述和默认提示。

## 案例库的使用方式

Skill 现在按三层证据判断，而不是强行“每条贴一个案例”：

1. `真实案例支撑`：能直接接到飞书选题台、商业动画成片、Austin商业视频Skill、Neurovia导演工作流、RunBY、MuseIn、车企内容营销等案例。
2. `相邻场景推演`：没有完全对应案例，但可以从用户人设和已有案例合理推演。例如新 Agent 框架可以推演到飞书执行台的分工、状态和验收；新视频模型可以推演到商业视频交付里的返修和成片验收；新设计工具可以推演到封面Skill、品牌资产库和小红书卡片生产。
3. `只作观察`：来源很热，但无法接到用户业务现场、四个方向或可展示资产，只能暂存或不建议制作。

这能避免两个问题：一是过度依赖已有案例导致选题范围变窄；二是完全脱离案例导致输出泛化、AI味重。

Skill 还必须区分 `热点钩子` 和 `我的内容`。遇到 Claude Code、Claude Design、Vercel Eve、Seedance、小云雀、Runway、Kling 等明确热点名时，可以把名称保留在标题或Brief里做入口，但标题必须落到“我会怎么测、怎么改造、怎么验证”的业务动作上。

## 三阶段主编工作流：先筛选，再标题工作坊，最后打包字段

最新规则不是“热点映射到母场景后生成标题”，也不是“先填字段再拼标题”。每条候选必须分三阶段处理：

1. `主编筛选`：只判断这条值不值得我做，不写标题。
2. `标题工作坊`：至少发散 5 个不同标题方向，不能只在同一句式里换词。
3. `标题自审`：选出最像用户、最有点击理由、最不模板的一条，然后才打包飞书字段。

`主编自由稿` 是用户拍之前写给自己的判断备忘，约 120-220 字，不是字段清单。它要回答：

1. 这个来源真正触发了什么；
2. 它和我的哪个真实或相邻业务现场有关；
3. 旧流程原来怎么做，谁参与，卡在哪里；
4. AI 介入后具体少掉、合并、重写或字段化了哪一步；
5. 我作为懂营销、懂内容、懂导演、正在做 AI 业务系统的人，保留什么关键判断；
6. 我不能声称什么，缺什么证据；
7. 最后能展示什么证据：流程图、字段表、Brief、分镜、封面、成片、返修清单、复盘数据或案例截图。

`点击钩子` 不是标题模板，而是点击理由。它必须来自 `标题工作坊` 和 `标题自审`，说明这条内容靠什么真实痛点、反常识、踩坑、结果差距、返工、交付风险或业务现场把人拉进来。`观众为什么会点` 要具体到目标观众的工作焦虑、效率损耗、内容生产卡点或业务判断困惑。

这些内容会压缩成飞书前台最重要的字段：

- `主编筛选`：只判断值不值得做，不写标题；
- `主编自由稿`：自由判断稿，防止结构化字段和标题模板化；
- `标题工作坊`：多个标题方向，用来防止一条模板套到底；
- `标题自审`：最终标题为什么被选中，为什么其他方向被淘汰；
- `点击钩子`：标题靠什么抓人；
- `观众为什么会点`：目标观众为什么愿意点进来看；
- `我的真实矛盾`：这条内容背后，用户自己的真实业务冲突是什么；
- `选题判断`：这条到底值不值得做，为什么；
- `原始钩子`：来源里真正能抓人的热点、工具、承诺或痛点；
- `我的切入`：为什么这条和用户有关，落在哪个业务现场；
- `我准备怎么讲`：如果拍，开头怎么进入，主体怎么展开，证据怎么摆；
- `可展示证据`：能展示什么，缺什么就直接说缺什么。

旧字段 `一句话Brief / 我的场景拆解 / 我的思考点 / 重点体现` 仍可保留，但它们必须从三阶段判断里自然抽出来，不再是默认前台阅读重点。写不出筛选、自由稿、标题工作坊、自审、点击理由、`我的真实矛盾` 和这张提案卡的内容，不允许包装成 `今日最值得做`。

## 第一人称工作备忘

前台字段必须像用户自己在拍摄或写稿前的备忘，而不是助理写给用户的分析报告。

避免：

- `用户当前正在搭...`
- `这条适合用户...`
- `用户可以用...`
- `它能帮助用户...`

改成：

- `我现在正在搭...`
- `这条我今天值得做，因为...`
- `我会拿它去测...`
- `我能展示的是...`

尤其是 `选题判断 / 我的切入 / 我准备怎么讲 / 可展示证据 / 一句话Brief / 我的场景拆解 / 我的思考点 / 重点体现`，都要用第一人称现场口吻。`我准备怎么讲` 要像拍摄前给自己的备忘，而不是“建议用户如何展开”。

## 自动链路如何真正使用案例库

`scripts/editorial_skill_runner.py` 不再把完整案例库整篇塞进 prompt 后让模型自己找重点。现在流程是：

```text
候选内容
→ 代码按关键词和栏目匹配 1-3 个母场景
→ prompt 注入 persona-brief.md + 每条候选的关联母场景候选 + 热点钩子候选 + 场景依据候选
→ Skill 必须先写出“主编自由稿”，再完成业务现场复盘：旧流程、卡点、AI改造、人保留判断、可展示证据
→ Skill 再写点击钩子和观众为什么会点
→ Skill 从自由稿和点击理由输出第一人称主编提案卡：主编自由稿 / 点击钩子 / 观众为什么会点 / 我的真实矛盾 / 选题判断 / 原始钩子 / 我的切入 / 我准备怎么讲 / 可展示证据
→ Skill 输出 热点钩子 / 普通人会怎么讲 / 我会怎么讲 / 场景依据 / 真实或相邻案例 / 我的改造动作 / 需要补的证据
→ Skill 再输出 关联母场景 / 借用方式 / 不能声称的部分 / 我的真实或相邻场景
→ 最后才生成 我的场景拆解、我的思考点、重点体现和可发布标题
```

这样做的目的，是避免“看起来读了案例库、实际输出还是泛模板”。模型必须先说明这条内容如何连接用户的真实/相邻场景，并判断它是 `真实案例 / 相邻推演 / 仅热点观察`，再决定是否值得进入候选。

## 和代码的边界

代码负责：

- 采集 AIHOT、公众号、抖音、RSS、网页；
- 标准化 ContentItem；
- 去重、运行批次、写入飞书；
- 做第一层候选筛选和排序。

Skill 负责：

- 判断这条内容能否接到用户真实业务现场；
- 把热点/对标内容改写成用户自己的语言；
- 使用案例库提炼主编直觉，并在没有完全对应案例时做合理相邻推演；
- 降低 AI 味和模板味；
- 输出能直接给人审查的选题字段；
- 先做主编筛选，再做标题工作坊，再做标题自审，最后抽字段，避免从一个标题模板变成五个标题模板，也避免标题正确但没人想点。

后续如果要把 Skill 串进自动链路，建议新增一个独立编辑层，例如：

```text
ContentItem -> code 初筛 -> ai-account-editorial-director -> 04 分析与选题
```

不要把 Skill 的人设判断继续拆成大量硬编码标题模板；代码只做采集、去重、清洗和质量校验，标题与字段的生成应来自主编筛选、标题工作坊、标题自审和点击理由。
